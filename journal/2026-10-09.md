# 2026-10-09

Identifying the best parameter optimisation method for neural ODEs for project Wilson-Cowan. 
There is rich literature on solving neural ODEs. We want to incorporate some of the relevant lessons without going down the rabbit hole too much. 

## Current state 
Observation: Loss goes to nan only a few steps into gradient descent. Initially observed on single-trial, 1ms bin data. Reproducible on trial-averaged data larger bin (10ms) as well. 
Further investigation: This seems to be due to the value of I blowing up during the rollout rather than due to one of the parameters blowing up. Confirmed both empirically. 
Conjecture: F' * dt/tau must be below a stability limit of the integrator, but gradient descent pushes the parameters over the threshold due to the absolute Adam steps. At lr=1e-3, tau moves by 1ms per step whereas E_max and I_max barely move. 
Where dI/dt = F(I).
Proof: 

Linear stability argument: 
with h = dt/τ_I:
 I_t+1 = I_t + h · F(I_t), where F(I) = −I + (I_max − I) · relu(u(I))
 δ_t+1 = (1 − h·k) · δ_t, with k = −F′(I*)
So each step multiplies the deviation by λ = 1 − h·k:

ODE τ·dI/dt = −kI always decays, for any τ > 0 (if k > 0). The blow-up is purely a property of the discrete map.

The above shows the linearised solution of one variable. A more robust proof requires the computation of the stability limit of the integrator from the eigenvalues of the Jacobian. 

## Ideas
We want to ideally find a parameter optimisation method that
- is stable over a long roll-out 
- learn the underlying dynamics 
- is generalisable for other neural ODE type of questions beyond the wilson-cowan project. 

What we don't want 
- Just naively reject non-finite updates or implement early-stoppping. This doesn't address the actual objective of learning the underlying dynamics, and artificially creates stability.
- Hard code parameter limits that need to be hand-tuned. This is not generalisable and also doesn't address the stability limit of the integrator. 
- Force the current format of parameter_optimiser + gradient descent. If we come up with a more principled method that can be generalised, that's also fine. We want to explore different methods if necessary, but don't change the code structure purely for the sake of being novel. 

Possible directions (no need to heed to this list, just initial ideas)
- Use a different integration method - e.g. exponential-Euler - using linear leak exactly with each step? Adaptive stiff solvers?  --> This addresses the actual numerical instability we saw 
- make step sizes relative to each parameter's scale --> addresses how quickly GD reaches the instability limit 
- shorten the horizon the gradient flows through --> reduces forward-pass overflow, but wouldn't prevent it completely 

## Experiments
Real data, trial-averaged, 10 ms bins, objective C, seed model2, all 3 discover mice (fit per mouse, so free), 4000 Adam steps, lr 1e-3, deterministic XLA (repeat run bit-identical). Stimulus now fed at the predicted bin (stim[t], was stim[t-1]): responses peak in the pulse bin, so the old 1-bin lag was unfittable.
Test FVU per popluation (MSE / that population's train var), mice M150605 / M150609 / M150823. Ceiling = train-fold condition average predicting test fold.

- [x] Per-population loss: I was 83/92/98% of the old pooled loss. Fix lets E drive the fit, but E transients need small τ_E -> hits the Euler limit sooner. Not judgeable alone.
- [x] Exponential Euler (leak solved exactly per step, X_new = X∞ + (X−X∞)·exp(−dt(1+g)/τ); bounded in [0, X_max) for any dt/τ). Integrator held, but GD then drives τ_I -> 0 (I faster than a 10 ms bin in M150609) and Adam's absolute steps push τ_I negative -> exp overflow.
- [x] log τ: the decisive fix. τ > 0 by construction, steps become relative (~0.1%/step). First fit that learns dynamics: M150605 post-pulse silence + ~200 ms rebound in E and I.
- Exp. Euler adds little loss-wise (3a ≈ 3b) but is the only guarantee: 3b reaches dt/τ_E = 2.1, fatal for Euler; 3a stayed < 1 by luck of slow relative steps. Cost +25%/step.
- Open: not converged at 4000 steps (best = last step). Unphysical signs remain (XE < 0 M150605, s0_S < 0, W_II < 0). E ceiling > 1 in M150609/M150823: their E is mostly noise (5–10 test trials/condition), so they can't rank methods on E.
- Generalisable: all three fixes are model-agnostic (variable scaling, positivity via log, stable integration of leaky dynamics).

Code: per-channel `loss_scale` (n, 2) and the `log_` convention are in the repo (uncommitted); exp. Euler only in the scratchpad harness (`model2_ee.py`).
