# Code Audit — 2026-05-23

Full audit of the EDGAR codebase against the Tilbury et al. paper (`paper/Tilbury.pdf`),
focused on whether the implementation faithfully reproduces the described
AI-equation-discovery pipeline and whether anything in the code can hang,
crash, or silently corrupt a run.

Read static, then exercised every layer — tests, data loader, sandboxed
scoring, prompt build, fake-LLM end-to-end pipeline, deduplication on
synthetic populations, and the schedule.

---

## 1. Audit method

### Static
- Read every module in `src/`, every test under `tests/`, the
  `orientation_tuning` project end-to-end, and the relevant prompts.
- Walked the paper's Methods section and built a checklist of paper claims
  → expected code locations.

### Executed
- `pytest -m "not live"` (98 tests, 14 live deselected): **all pass** in
  ~97 s.
- `python scripts/check_loader.py projects/orientation_tuning/config.yaml`:
  loader runs, returns the expected 3-tuple shape, 16 cells survive
  filtering on the dummy `.npy`.
- Manually compiled the seed Gaussian to JAX and called
  `scoring._score_one_model` in its sandboxed subprocess —
  init loss 211 → final 132 with 1000-step ADAM at `lr=0.003`.
- `python -m edgar.cli test-fake` (end-to-end with `FakeLLM` cycling through
  `Program1`, `InvalidProgram`, `ProgramSolution`): the run completes,
  population.jsonl + island_census.jsonl + run.log + family_tree.html all
  written, `InvalidProgram` is sandboxed by `_score_one_model` and gets
  `inf` loss as expected.
- Replayed `TaskSpec.schedule(gen)` for n=12 generations to confirm the
  explore→exploit flip at gen 6 and the raw temperature range [1.40, 2.00].
- Drove `deduplicate(...)` on a synthetic 12-vs-12 island pair where every
  program in island 1 is a near-duplicate of one in island 0 — to verify
  the paper's "if ≥75% overlap, reset worse island to seeds" rule.
- Drove `spawn(...)` on an empty island to confirm the failure mode that
  emerges from the dedup bug above.
- Mocked `call_llm` to raise an uncaught exception mid-batch to confirm
  whether `asyncio.gather` swallows it (the overview claims it does).

## 2. Summary scorecard

| Component | Faithfulness | Notes |
|---|---|---|
| Two-function program (model + parameter estimator) | ✅ | `Program.code.{model, param_est, model_jax}` matches the paper. |
| NumPy → JAX two-step generation | ✅ | `translate_programs` runs as a second LLM call. |
| Sandboxed scoring with timeout | ✅ | `multiprocessing.get_context("spawn")` + `queue.get(timeout)`; subprocess killed on timeout. Verified empirically. |
| Adam gradient descent on training trials | ✅ | `_optimize` uses `optax.adam`; keeps best-of-trajectory `flat`. |
| Cross-validated MSE on test trials | ✅ | `_eval_loss` is mean over test split. |
| Complexity penalty | ⚠️ | Added in code, but **effectively zero** in `orientation_tuning` because the loss is scaled ×10 and responses are L2-normalised to ‖R‖=100. See **Finding F1**. |
| Cell + trial 50/50 splits | ⚠️ | Splits are random, not interleaved as the paper says (Methods, *Data Partitioning Strategy*). **F2**. |
| Activity / concentration filters | ⚠️ | Filter thresholds wired through, but the loader also reuses `activity_threshold` as a per-cell *trial cap* and drops zero-response trials, which is not in the paper. **F3**. |
| `n_islands=8`, `B=6`, `cps=12`, `n_migrants=2` | ✅ | Defaults match the paper. |
| Prune to top-N per island | ⚠️ | Code prunes to `critical_population_size - n_migrants` (= 10 with the defaults), not to 12 as the paper text says. **F4**. |
| Dedup: cosine > 0.99, |ΔS| < 0.025 | ❌ | Code defaults to `cosine_tol=0.95`, `loss_tol=0.01`, and the dispatcher never passes the paper values from config. **F5**. |
| Dedup: reset worse island to seeds at ≥75% overlap | ❌ | Not implemented at all. The current `deduplicate_outer` just deletes duplicates one-by-one — and in the extreme case **leaves an island empty**, which then crashes `spawn()`. **F6 — highest severity bug.** |
| Boltzmann migration over scores | ✅ | `boltzmann_sample` matches the paper formula (Z-normalised, T-scaled). |
| Migration topology | ✅ | Ring topology by default; per-island sends to `islands[topology[i]]`. |
| Temperature schedule T(i) = e^(-i/N) | ⚠️ | Code emits **1 + e^(-i/N)** (range [1.37, 2.0]), then `migrate` warps it back via `(T-1)^4`. The same un-warped value is sent to the LLM as the sampling temperature. **F7** (Anthropic 400, plus paper drift). |
| LLM role split (lightweight / mid / thinking) | ❌ | Paper specifies mid for 2/3 of f, thinking for 1/3, lightweight for translation. Code rotates a single list **per generation**, not per program within a generation. **F8**. |
| Parents are sorted worst→best in the prompt | ❌ | Parents are sampled with `uniform_sample` (returns `set`), stored in `birth.parent_indices` in arbitrary order, and inserted into the prompt template in that order. The prompt text and image legend both claim worst→best ordering. **F9**. |
| Multimodal image feedback | ✅ | Image generated, attached as `BinaryContent` PNG, passed to the LLM via pydantic-ai. |
| Failed LLM calls leave `None` code, are filtered | ⚠️ | Mostly true via `call_llm`'s internal try/excepts, but **`asyncio.gather` is NOT called with `return_exceptions=True`** — contradicts `overview.md` + `CLAUDE.md` and crashes the generation on any uncaught exception (e.g. `RuntimeError`, `asyncio.CancelledError`, anthropic 400, transport errors). **F10**. |
| Family-tree HTML + island census | ✅ | Both written under `try/finally`, even on crash. |

✅ = matches paper / works correctly under test
⚠️ = drifts from paper or has surprising behavior, not catastrophic
❌ = real bug or non-trivial spec drift

## 3. Findings (ranked, highest severity first)

### F6 — `deduplicate_outer` can empty an island, then `spawn` crashes
Severity: **critical**. Reproduces with synthetic data.

**Paper** (Methods → *Population Management and Deduplication*):
> Similarity is assessed both within islands and between island pairs — if
> two islands share ≥ 75% of the critical population size in duplicates,
> the island containing the lower scoring solutions is **reinitialized
> with the seed models**.

**Code** (`src/evolution/island.py:261-303` and `:306-321`):
- `deduplicate` uses `min_island_size = 0.75 * critical_population_size`
  only as a **gating condition** for whether to bother running the outer
  pass.
- The outer pass itself just removes the higher-loss program of every
  duplicate pair, with no concept of "if too much overlap, reset to seeds".

**Empirically demonstrated.** With island 0 = 12 distinct programs and
island 1 = 12 programs that are each a duplicate of one in island 0
(loss diff 0.005 < default tol 0.01):

```
before dedup: |I0|=12  |I1|=12
after  dedup: |I0|=12  |I1|=0
```

The next generation's `spawn(...)` calls `uniform_sample(programs=[],
k=num_parents=2)` and raises `ValueError: k=2 exceeds number of programs
sampled from 0`. The `try/finally` in `src/run.py:119` catches it and
saves the population, but the run is dead.

Fix sketch: in `deduplicate`, after running the outer pass, count
within-island survivors. If any island fell below some threshold
(or, faithful to the paper, if `len(duplicates_with_other) >=
0.75 * cps` *before* removal), reseed that island from
`spec.seed_programs` instead of letting it empty out.

### F5 — Deduplication tolerances are wrong and not configurable
Severity: **high**.

**Paper**: cosine similarity > 0.99 **and** score difference < 0.025.

**Code** (`src/evolution/island.py:306`):
```python
def deduplicate(islands, population, evolution,
                loss_tol: float = 0.01,
                cosine_tol: float = 0.95) -> None:
```
Defaults are 0.01 / 0.95. `run.py:107` calls `deduplicate(islands,
population, spec.evolution)` with no overrides, and there is no `loss_tol`
or `cosine_tol` field in `EvolutionConfig` to override from YAML.

Net effect: too aggressive — programs that are merely correlated (not
identical) get pruned, and a 0.01 loss-difference window is 60% tighter
than the paper's 0.025.

Fix sketch: pull tolerances from `evolution.dedup_loss_tol` /
`evolution.dedup_cosine_tol` (add to `EvolutionConfig` and
`config_default.yaml`); change defaults to the paper values.

### F1 — Complexity penalty is effectively zero on `orientation_tuning`
Severity: **high**.

**Paper**: `S = -mean(MSE) - λ·dim(β)`, λ = 0.01 — chosen so each
additional parameter costs ~2% of the attainable improvement.

**Code**:
- `_worker` (`scoring.py:91`): `penalty = config["param_penalty_weight"] *
  program.n_params`. With λ=0.01 and 4 params for a Gaussian seed,
  penalty = 0.04.
- `orientation_tuning/data_loader/load_data.py:103`:
  `return 10 * jnp.mean(..., axis=-1)` — scales MSE ×10.
- `_normalize_response` (same file, `:125`):
  `100 * response / ||response||` — scales magnitudes ×100, so squared
  error scales ×10⁴ on top of that.

Net effect: I measured a seed model's loss at **131** after optimisation
(see §1, "Executed"). A 0.04 penalty is **0.03% of the loss**, not the
paper's ~2%. The complexity penalty does essentially nothing on this
project; the LLM is free to evolve unboundedly complex programs without
paying.

Fix sketch: pick *one* of these and document it:
1. Drop the ×10 in `loss_fn` and the ×100 in `_normalize_response` —
   normalise responses to unit L2 as the paper says, leave the MSE
   un-rescaled.
2. Scale `param_penalty_weight` up to match the loss magnitudes
   (~10⁴ × paper value).
The first is closer to the paper; the second is a one-line config tweak.

### F10 — `asyncio.gather` does not use `return_exceptions=True`
Severity: **high** (silent dependency on a documented-but-false contract).

**`overview.md:211-212` and `CLAUDE.md:105`** both claim:
> LLM calls use `asyncio.gather(return_exceptions=True)`: failed calls
> leave None code on the program and get filtered out at scoring time —
> no crash.

**Code** (`src/llm/generate.py:124, 171, 204`):
```python
await asyncio.gather(*[ _generate_one_model(...) for p in programs ])
```
No `return_exceptions=True` anywhere.

Empirically verified: I mocked `call_llm` to raise `RuntimeError` on the
2nd of 3 concurrent calls, and `generate_models` propagated the exception
out, killing the generation.

In practice this is partially papered over by `call_llm`'s own
try/excepts (`UnexpectedModelBehavior`, retryable HTTP, `ModelHTTPError`
non-retryable on final attempt). But anything that escapes those —
`asyncio.CancelledError`, generic `RuntimeError`, `ConnectionResetError`,
the Anthropic 400 from F7, a bug in `plot_fn`, etc. — will take down the
whole generation, and the docstring tells the next agent the opposite.

Fix: either add `return_exceptions=True` and filter `None`-results
downstream (close to what the docs claim), or update the docs to reflect
the actual behavior. The docs-vs-code mismatch is itself the bug.

### F8 — LLM role split per program is not implemented
Severity: **medium** (paper deviation; runs still work).

**Paper** (Methods → *LLM Selection and Task Distribution*):
- Lightweight model = translation
- Mid-range = parameter estimators and **2/3 of neuron models**
- Thinking model = **1/3 of neuron models**

**Code**: `LLMsConfig.model_llm` accepts a list, but `run.py:86`
selects one model **per generation** via `llms.model[gen % len(llms.model)]`.
Within a generation every concurrent LLM call uses the same model.

The `param_est_llm` and `jax_model_translator_llm` are scalars, not split
by role.

Fix sketch: at the `_generate_one_model` call site, pick the LLM per
program (e.g. round-robin by `program.birth.batch_index`, or stochastic
1/3-2/3 split), not per generation.

### F9 — Parents are not sorted worst→best in the prompt
Severity: **medium**.

**Paper** + `prompt_defaults.yaml` and `orientation_tuning/prompts.yaml`
both tell the LLM the parents are sorted worst→best (and the image
legend says "red = second best, green = best").

**Code path**:
1. `spawn` calls `uniform_sample(programs, k=num_parents, rng=rng)`, which
   returns a `set[int]` (`island.py:135-136`).
2. Caller does `list(uniform_sample(...))` (`island.py:90`) — `list(set)`
   has no order guarantee on integers, but in CPython it ends up in
   insertion-by-hash order; not score order.
3. `_resolve_parents(...)` returns parents in `parent_indices` order
   (`generate.py:47`).
4. The prompt template iterates `programs` in that order, and the plot
   colours them in that order.

Net effect: the LLM is told "worst → best" but actually receives them in
arbitrary order. Same for the diagnostic image's red/green coding.

Fix sketch: sort parents by `program_losses.discover.final` (descending)
right before `prompt_schema.build_prompt(...)` and before passing them to
`plot_fn`.

### F7 — Temperature schedule sends T ∈ [1.37, 2.0] to the LLM
Severity: **medium**.

**Paper**: T(i) = e^(-i/N_iter), so T ∈ (0, 1]. Migration is biased
toward elites at low T.

**Code** (`src/io/task_spec.py:230`):
```python
temperature = 1 + np.exp(-generation / n_generations)
```
…which is **1 + e^(-i/N)**, range [1.37, 2.0]. The same value is passed
unchanged to the LLM (`run.py:88` → `call_llm(..., temperature=...)`),
and only the migration path warps it back to (0, 1] via `(T-1)^4`
(`island.py:195`).

Consequences:
- Anthropic models reject `temperature > 1` with HTTP 400 (already noted
  in `journal/2026-05-23.md`, blocks A/B with Claude).
- Gemini accepts T up to 2.0 but the run is at effectively-max-creativity
  for the whole run; the paper's annealing is only visible in migration.

Fix sketch: keep `temperature` as the paper-spec e^(-i/N), and apply any
LLM-side rescaling at the call boundary (the temperature-warping
"option C" in the journal).

### F4 — Prune target diverges from paper
Severity: **low**.

**Paper**: "populations are pruned by keeping only the **12** programs of
highest score" (= `critical_population_size`).

**Code** (`src/evolution/island.py:118`):
```python
keep_n = evolution["critical_population_size"] - evolution["n_migrants"]
```
With the default `cps=12, n_migrants=2`, that's 10 — the prune step
leaves room for the 2 incoming migrants so the post-migration size is
≤ 12. Defensible (and arguably equivalent to the paper net of book-keeping
order), but it does mean the in-island population fluctuates between 10
and ≤ 14 across the generation cycle, not the steady 12 the paper
suggests.

Fix sketch: either keep as-is and document the intent ("post-migration
size ≤ cps"), or prune to `cps` and let the dedup step absorb any
overflow.

### F2 — Cell and trial splits are random, not interleaved
Severity: **low** (statistically equivalent in expectation).

**Paper**: `c1, c3, c5, …` train cells; `c2, c4, c6, …` test cells. Same
pattern for trials.

**Code** (`orientation_tuning/data_loader/load_data.py:70-77`): uses
`rng.permutation(...)`. Reproducible given a seed, but not interleaved.

Probably fine for fitting, but it means the discover/validate split
shuffles differently each `random_seed`, which makes cross-run comparison
slightly noisier than the paper's deterministic split.

---

### F3 — Loader drops zero-response trials and caps per-cell trial count
Severity: **low–medium** (changes the data distribution shown to models).

**Code** (`orientation_tuning/data_loader/load_data.py:43-60`):
- `n_trials_small = int(n_trials_raw * activity_threshold)` —
  reuses the activity *cell* threshold (0.4) to set a per-cell
  *trial* cap (240/600).
- For each surviving cell, only the first `n_trials_small` trials with
  positive response are kept.

The paper does no such thing — it bins responses and works on every
binned (cell, stimulus, repeat) tuple. The current loader (a) silently
truncates data and (b) over-represents positive trials. This is one of
the more concrete deviations and worth fixing before we publish any
numbers.

Fix sketch: drop the trial cap entirely; keep all trials and let the
gradient descent see the real response distribution. If you need to keep
sizes bounded for compute, sample uniformly across trials, not by
response polarity.

### Misc (low severity)

- `island.py:13` docstring says `census[island_id][generation]`. Reality
  (per `run.py:110`'s `census.append([set(island) for island in islands])`)
  is `census[generation][island_id]`. The transpose matters when someone
  reads the JSON.
- `_generate_one_param_est` (`generate.py:144`) always uses
  `mode="explore"` regardless of the current generation's mode. Probably
  intentional (param est doesn't need explore/exploit) but worth
  documenting.
- `_translate_one_model` hardcodes `temperature=1.0` (`generate.py:188`).
  Acceptable but un-noted.
- `plot.py:24` uses `np.random.choice(...)` directly — sample selection
  is non-deterministic across runs and not tied to `spec.rng`. Minor
  reproducibility leak.
- `plot.py:11` docstring says input is `X_disc_train`, but `run.py:91`
  passes `X_discover[1]` which is `X_disc_test`. Docstring out of date.
- `log_generation` (`logging.py:153`) writes `model=<CyclingModel object
  at 0x…>` when an LLM is a `Model` instance rather than a string;
  cosmetic.
- `scripts/ping_llms.py:41` prompts the LLM for "Nyoki and something
  else" but checks for `"12345"` (`:50`). The script *always* reports
  failure even when the API is healthy.
- `ResponseSchema.default_params` (`response_schema.py:32`) is typed as
  plain `dict` with no validation that values are numeric. The prompt
  asks for floats but nothing enforces it; non-numeric values would
  poison `Program.default_params` and silently set `n_params=None`
  (warning issued but loss falls through to `inf` later — see `notes.md`
  bullet 1).
- The `compact` log line `scored=67%` (visible in the fake-LLM run log)
  counts `inf` losses as "not scored". A program that *was* scored and
  returned `inf` is a different state from one that was never scored;
  worth disambiguating.

## 4. What's in good shape

- Test coverage in `tests/evolution`, `tests/scoring`, `tests/llm`, and
  `tests/system` is genuinely thorough; the fake-LLM end-to-end test is
  the right level of abstraction and it caught the `InvalidProgram`
  sandboxing path in this audit run.
- The sandboxed scoring path (subprocess + timeout) is robust — fed it
  malformed JAX (the `jnp.zeros(("c"))` `InvalidProgram`) and it returned
  `(inf, inf, None, None, None)` cleanly without taking down the parent
  process.
- The `try/finally` in `run.py:119` saves `population.jsonl` and
  `island_census.jsonl` on every code path including crashes; the
  fake-LLM `test_saves_on_error` exercises this and passes.
- `Config.from_yaml` deep-merging behavior matches the docstring; all
  `test_io/test_config.py` paths (perfect, missing field, missing
  subfield, invalid topology, additional field) round-trip correctly.
- Anthropic dispatch in `_build_model` (`llm_calling.py:34-58`) is clean
  and the per-provider ping test infrastructure is already in place.

## 5. Suggested fix priority (if we want to publish faithful results)

1. **F6** — `deduplicate_outer` reset-or-empty bug. Single bug that can
   crash a run. Fix the missing reset behavior, or at minimum guarantee
   no island is left empty.
2. **F5** — Dedup tolerances. Cheap to fix and wrong by default.
3. **F1** — Complexity penalty scale. Without this the AI is essentially
   unpenalised for complexity, which materially changes what equation it
   converges to.
4. **F10** — `asyncio.gather` either takes `return_exceptions=True` or
   the docs need updating. Don't leave the docs lying.
5. **F9** — Parent ordering in prompts. The image-feedback prompt
   specifically claims green = best; right now it's just random.
6. **F8** — LLM role split. The paper's central methodological claim is
   that this split is what made it work in 45 minutes for $8.25. Without
   it we can't honestly claim to be reproducing the result.
7. **F7** — Temperature schedule. Quick to fix and unblocks the Anthropic
   A/B already on the journal's "next" list.
8. **F3, F4, F2** — Data loader truncation, prune target, split style.
   Tidy these up while we're in here.
9. **Misc** — Address piecemeal; the ping_llms.py mismatch is the only
   one with operational impact.
