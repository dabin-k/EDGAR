## Things to flag

### No GPU on this box
`nvidia-smi` reports `couldn't communicate with the NVIDIA driver`. JAX's CUDA12 plugin therefore fails to initialize on every scoring subprocess and prints a 10-line traceback (`CUDA_ERROR_NO_DEVICE`) before falling back to CPU. JAX itself works fine on CPU — `final` losses get computed correctly — but the noise will drown real errors in `run.log`.

**Workaround:** prepend `JAX_PLATFORMS=cpu` to runs (or export it in the shell). I'm doing this for all real-LLM runs from here on. Worth thinking about whether to make this the default in `edgar/cli.py` when `nvidia-smi` is absent, but not in scope today.

### Data file size mismatch (low risk)
User said the manually-transferred data file is ~859 MB. On this box `data/gratings_drifting_GT1_2019_04_12_1.npy` is **111 MB**. Filename matches; nothing else with that pattern in the data dir. Either the user mis-remembered the size, or this is a reduced/decimated copy. The seed phase loaded it without error in `test-fake` so the contract is satisfied. Flagging in case downstream the loss values look unexpected.
