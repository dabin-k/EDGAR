- `island_census.jsonl` has 2 entries (seed-phase saves an empty `census=[]`;

### Relaunch path that exists today
- **Fresh run, same config**: every run drops a frozen `task_spec.yaml`
  alongside its outputs. `edgar run path/to/task_spec.yaml` re-runs the same
  experiment (same seeds, same prompts, same data, same LLMs, same evolution
  knobs) but into a brand new output dir under `program_databases/MM-DD/HH-MM-SS/`.
  `Config.from_taskspec()` is the loader. This is enough to repro a config
  but **loses all 98 evolved programs from the dead run**.

  ```bash
  conda activate edgar
  python -m edgar.cli run program_databases/05-26/14-54-15/task_spec.yaml
  ```

- **Resume from checkpoint**: not supported. `run.run()` is monolithic — it
  always constructs an empty `Population()`, runs the seed phase, then iterates
  `for gen in range(n_gens)`. There is no `--resume`, no checkpoint loader, no
  CLI subcommand for it.

## Decisions

### Design for `edgar resume <run_dir>`

Goal: when a run dies (Ctrl-C, network drop, OOM, LLM provider outage,
laptop closed), the user runs one command and the loop picks up at the next
generation, writing into the same output dir.

**CLI surface (Recommended):**
- New subcommand: `edgar resume <run_dir>`. Explicit, discoverable,
  unambiguous. Reuses `Config.from_taskspec(<run_dir>/task_spec.yaml)` to
  rebuild the `TaskSpec`.
- Alternative considered: have `edgar run` auto-detect a half-finished run and
  prompt. Rejected — too magic; users may want to deliberately re-run fresh
  for a different seed.

**State restoration (all building blocks already exist):**
- `Population.load(<run_dir>/population.jsonl)` — already implemented.
- `load_island_census(<run_dir>/island_census.jsonl)` — already implemented.
- `islands = [set(s) for s in census[-1]]` — restored island membership.
- Resume index: `start_gen = len(census)` (next 0-indexed generation to run).
- Skip seed phase entirely on resume (it's already in the population).
- Skip `spec.save(run_dir)` — `task_spec.yaml` is chmod read-only.

**Where output goes:** same dir. `population.save()` and
`save_island_census()` already do atomic full-rewrites, so re-opening the run
dir is safe. `run.log` gets appended to with a clear "──── RESUMED ────"
banner.

**Status semantics:** on resume, set `state=running`, keep original
`started_at` (read from existing `status.json`) so total wall time across
resumes is recoverable from gen timing rows alone.

**Validation guards (small, cheap, falsifying):**
1. Refuse to resume if `status.state == "complete"` (would re-run validation
   on a finished run).
2. Refuse if `len(population) == 0` (nothing to resume from — user should use
   `edgar run` instead).
3. Sanity: every idx in `census[-1]` must be `< len(population)`. If not,
   the run dir is corrupt; fail loudly.
4. If `current_gen >= n_gens - 1` and validation losses are unset, jump
   straight to the validation phase rather than re-entering the loop.

**Known imperfections (accept, document, don't fix):**
- `spec.rng` state is lost. With a fixed `run.random_seed`, the resumed run's
  spawning/migration draws diverge from what a continuous run would have
  produced. LLM responses are non-deterministic anyway, so bit-reproducibility
  was never on offer. Note this in the resume banner so the user isn't
  surprised.
- `metrics._gen_rows` starts empty on resume — wall-clock totals reflect
  post-resume time only. Per-gen timings are still accurate.
- `image_feedback/` from the dead run is preserved; new gens append.

**Scope estimate:** ~50 LOC in `edgar/run.py` (factor the loop body into a
helper, add a `resume_from` kwarg), ~15 LOC in `edgar/cli.py` (new subcommand
+ wiring), ~30 LOC test using `tests/system/fake_runner` (run 2 gens, drop
state, resume, assert final population length and that gen 0/1 weren't
re-scored).

### Files to touch

## Done (implementation)

### `edgar resume <run_dir>` — shipped
- New subcommand wired through `edgar/cli.py:_build_and_resume`. Reads
  `status.json` first, refuses to resume `state=="complete"`, and loads
  `Config.from_taskspec(<run_dir>/task_spec.yaml)`. Usage:
  ```
  python -m edgar.cli resume program_databases/05-26/14-54-15/
  ```
- `edgar/run.py:run()` grew a `resume_from: str | Path | None` kwarg. When
  set:
  - `_prepare_resume()` restamps `spec.creation_timestamp` so `spec.output_dir`
    points at `run_dir` (writes land back in the same place).
  - Skip `spec.save()` (`task_spec.yaml` is chmod read-only).
  - Open `run.log` in append mode with a `RESUMED at <ts>` banner.
  - Preserve `started_at` from existing `status.json`.
  - `population = Population.load(...)`, `census = load_island_census(...)`,
    `islands = [set(s) for s in census[-1]]`, `start_gen = len(census)`.
  - Pre-populate `metrics._gen_rows` from `read_metrics()` so the dashboard's
    `last_metrics` reflects the full timeline, not just post-resume.
  - Skip the seed phase block entirely.
  - Loop runs `range(start_gen, n_gens)` instead of `range(n_gens)`.

### Stale-shell truncation
- New `_drop_trailing_unscored(population)` walks back from the end of the
  loaded population and drops programs while `discover.final is None`. These
  are spawn shells from the crashed gen that never got scored. Pruned-but-
  scored programs from earlier gens are preserved (their `final` is a float
  or `inf`, not `None`). Without this, resume would leave ghost entries in
  `population.jsonl` and inflate the final program count.

### Validation guards
- `_validate_resume_state` refuses to resume in three cases with clear
  messages: empty population (seed phase never finished), empty census
  (gen 0 never finished), or `len(census) >= n_gens` (run reached validation;
  nothing to resume). Also sanity-checks that all census indices are
  in-range.

### Pre-existing bug fixed in passing
- `Population.load()` was deserializing the `NotValidated` sentinel as the
  bare string `"NOTVALIDATED"` (matching how `save()` writes it for JSON
  safety). This wasn't a problem before because nothing called `load()` in
  the live pipeline. On resume it broke `rank()`: validated programs include
  any whose `validate.final` is not a `NotValidated` instance, so the strings
  slipped through, then `sort` compared `str < float` → `TypeError`. Fix:
  reconvert the string back to a `NotValidated()` instance at load time.

### Tests
- `tests/system/test_resume.py` — four tests, all green:
  1. `test_resume_after_midrun_crash` — drives the fake_runner to crash mid
     gen-1 `score()`, then resumes. Asserts census reaches `n_generations`,
     stale shells were dropped (final count == `n_seed + n_gens*n_per_gen`),
     pre-crash discover losses survived unchanged, status flipped to
     `complete`, and `metrics.jsonl` contains both pre-crash and post-resume
     gens. Also checks the RESUMED banner is in `run.log`.
  2. `test_resume_refuses_completed_run` — running `run(resume_from=dir)` on
     a finished run raises `ValueError("already has * completed gens")`.
  3. `test_resume_refuses_missing_dir` — nonexistent path raises
     `FileNotFoundError("does not exist")`.
  4. `test_resume_refuses_non_run_dir` — real dir without `task_spec.yaml`
     raises `FileNotFoundError("task_spec.yaml")`.
- All 8 existing `test_run_fake.py` tests still pass.

### Files touched
- `edgar/run.py` (+~75 LOC) — `resume_from` arg, helpers, gated seed phase,
  start-gen offset.
- `edgar/cli.py` (+~45 LOC) — `_build_and_resume`, `resume` subparser +

### Things to flag
- `spec.rng` state is not restored across resume. With a fixed
  `run.random_seed` the spawning/migration draws after a resume differ from
  what a continuous run would have produced. LLM responses are
  non-deterministic anyway, so bit-reproducibility was never on offer. Worth
  documenting in `overview.md` if/when it gets a "reproducibility" section.
- The pre-existing jaxlib/jax version mismatch in the test environment
  causes the scoring subprocess to fail and return `inf` for all fake-LLM
  test programs. Tests still function (we count programs, not validate
  losses), but the env should be fixed to get clean signal.
- `prepare_validation_scoring` clobbers `validate.final` unconditionally for
  alive programs. If the validation phase itself crashes mid-stream and a
  resume is attempted, those losses are lost. Not currently in scope —
  `_validate_resume_state` refuses to resume past `len(census) >= n_gens`,
  so this can't happen via the supported path. Worth lifting that
  restriction in a future iteration if validation-phase resumes turn out to
  matter.
