### `projects/burgers/bench/compare_3way.ipynb`
Loaders + prediction pullers, nothing precomputed to disk. Launch with

```
uv run --with pysindy --with jupyterlab jupyter lab projects/burgers/bench/compare_3way.ipynb
```

(`pysindy` is not a repo dependency and is not installed in `.venv`; only `sindy_predict` needs
it, and the import is guarded.)

| gives you | how |
|---|---|
| `bench` | `results/rescore_noisy.json` → tidy frame; reads `horizons_noisy_scored`, keeps the clean-scored MSE only as `mse_test_cleanscored` |
| `edgar` | walks the 9 `program_databases/burgers/burgers-nl*-r*` runs, best program per run, `sample_losses` per discover sample |
| `all_results` | the two concatenated on shared columns; MSE + skill pivot tables |
| `sindy_predict` / `stencilnet_predict` / `edgar_predict` | `(preds, targets)` for any single cell |
| `to_canvas` | either method's h-step-ahead preds onto one `(n_sensors, T)` field, NaN where unpredicted |

**EDGAR's persistence floor is recomputed on EDGAR's own tensors** (`edgar_persistence`, a
`data['x'][:, -1]` model through the project's `evaluate`), so its skill is internally consistent.

#### Two traps found while writing it
1. **`program.params` on disk is the last fit performed, not the discover fit.**
   `scoring.score()` overwrites `program.params` on every split (`scoring.py:596`) while keeping
   `sample_losses` from discover only, so for validated programs the saved params are the
   **validate**-split fit. Rolling them out on discover-test reproduces neither the init nor the
   final loss (idx 2 of `burgers-nl0-r2`: 1.30e-5 recomputed vs 1.582e-5 recorded).
   `edgar_predict` therefore refits via `_get_params` + `_optimize` on the requested split —
   verified to reproduce `sample_losses` to float32 on 3 programs.
2. **`burgers-nl001-r1` has two timestamps**, `12-57-20` (2 lines, aborted) and `14-45-46`
   (62, real). `edgar_runs()` keeps the larger population per run name.

`to_canvas` index mapping verified by pushing *targets* through it: max |canvas − field| = 0.0
(bench) and 3e-8 (EDGAR, float32 round-trip), EDGAR columns ⊂ test-block columns.

Provisional reading, **not** a result yet: EDGAR sits between SINDy and STENCIL-NET at low noise
and is the only method with non-trivial skill at nl=0.1. Before quoting any of this —

* **the protocols still differ** (bench = RK3 on a continuous RHS from every column seeded by one
  state; EDGAR = discrete AR map, m=5 lags, per-block restarts). Start sets differ at the edges,
  which is why the table is skill rather than raw MSE. Open item 4 of 2026-07-30, still open.
* **nl=0.1 has only ~2.1× headroom over persistence**, so that block measures noise robustness,
  not equation quality.
* **one seed per cell**; STENCIL-NET's own scatter was measured at ~3–5× on 2026-07-29.
* EDGAR's h=1 nl=0.0 cell (6.5e-7) is 9× better than its h=2 cell, which does not fit the
  monotone-in-h pattern of every other method — worth checking before trusting it.
