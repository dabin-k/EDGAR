## Burgers benchmark — current train/test process

**Data.** Shared coarse field `u_clean` (64, 4001) from `load_data.load_bundle()`; forcing `f(x,t)` known analytically. Noise levels swept: `[0.0, 0.01, 0.05, 0.1, 0.3]`. Config: `rollout_steps=2`, `train_cols=1001`.

**Shared scoring** (`load_data.teacher_forced_forecast` + `forecast_mse`). From every column with `rollout_steps` clean steps ahead (`n_starts = T − rollout_steps`), seed RK3 at the TRUE clean state, roll `rollout_steps` on the model's own RHS (`+` known forcing), score MSE vs the clean field over all restarts × steps × space. `rollout_steps` read from config `evaluate.rollout_steps`. Plot (`compare_sindy_stencilnet.py`) uses `forecast_mse_full`.

**SINDy** (`sindy/runner.py`, `compare_sindy_stencilnet.py`).
- `fit_pdefind` on the **full** noisy field (all columns), known forcing subtracted. Strong = finite-diff PDE-FIND; weak = `WeakPDELibrary` integral form. STLSQ, threshold 0.01.
- Recovered PDE → RHS (Lax-Friedrichs flux advection + central-diff diffusion + RK3), scored by the shared protocol. Unstable rollouts flagged + MSE-capped.

**STENCIL-NET** (`stencilnet/runner.py`, `sweep.py`).
- `MLPConv [7,64,64,64,1]`, ELU, ~8.9k params. Trained on the first `train_cols=1001` columns only.
- Forcing-aware forward+backward RK3 consistency loss (decay 0.9, `l_wd=1e-7`); noisy levels add a learnable latent-noise field (`l_n=1e-5`). Adam lr=1e-3, `ExponentialLR(0.9998)` after 15k epochs, 30k epochs total.
- **Training rollout horizon = scoring horizon** (both from config `rollout_steps`); consolidated from the former fixed `m=4`. Scored by the shared protocol.
- `sweep.py` sweeps a (noise × rollout_steps) grid; default `--rollout-steps 1 2 4 8`; per-run artifacts → `results/rollout<r>/`.

**Cross-validation status.** Scores are **not** cross-validated: the plotted `forecast_mse_full` spans the fitted region. SINDy fits on all columns (its `forecast_mse_heldout` is contaminated). STENCIL-NET trains on cols `[:1001]` so its `forecast_mse_heldout` is genuine, but the plot uses `_full`. `load_data.block_split()` (leak-free alternating-block train/test) exists but is unused.

## Clarification questions -- RESOLVED
- 1. What does "Forcing-aware forward+backward RK3 consistency loss" mean for STENCIL-NET? Why is it "forcing aware", and how is the backward loss used for training? How many backward steps do we compute the loss on? 
- - STENCIL-NET learns the spatial RHS operator N(u) of PDE u_t = N(u) + f. The loss is computed by integrating the field with Runge–Kutta method. Loss is calculated by both rolling the operator forward and backwards. Loss of each rollout is weighted by wd[j+1] = 0.9^(j+1)
- - loss = fwd + bwd + l_wd·‖W‖² (+ l_n·‖noise‖²) (runner.py:145-148) — so both directions contribute equally to the gradient.
- - "forcing-aware" : the analytic forcing f(x, t) is injected into the RHS at each Runge–Kutta integration step.  
- 2. Do we supply both SINDy and STENCIL-NET with the true forcing terms when analysing forced data? Is this what is done in the original paper for both methods? 
- - Yes. This seems to have been the explicit method for STENCIL-NET. For SINDy, it's possible that they only considered the unforced case. To be verified explicitly by reading through the paper. 

## Extra note on how STENCIL-NET works
- Create a stencil for every point. I our case, for every point u(x, t), a stencil consists in a length 7 vector containing -3:+3 spatial points (i.e. [u(x-3, t), u(x-2,t), u(x-1, t), u(x, t), u(x+1, t), u(x+2, t), u(x+3, t)].T)
- Train a 4 layer MLP (sizes : [7, 64, 64, 64, 1] with ELU between them) that takes in these length 7 vectors, and outputs a scalar value. The output is the estimate of net(u) (which is roughly du/dt for unforced burgers and du/dt - F if forced) at the given time. Note, net(u) == is the learned local stencil operator.
- How is the loss computed? STENCIL-NET never compares the du/dt values explicitly. Instead, we integrate the learned value net(u) over time using Runge-Kutta (RK3) method, and rollout m steps forwards and backwards. Loss is always compared against the observed valuse of u(x, t + \delta t)
- Noise parameter : the model infers both the clean signal and the noise. net.noise, which is a tensor with the same shape as the training data, is learnt during training as a network parameter. The MLP and noise tensor are co-optimised by the same Adam step on the same loss. But the noise isn't a part of the MLP (i.e. net.noise is not used during net.forward())
- - How is this noise "latent" used? Rollout is both seeded from the clean estimate and also evaluated against the clean estimate u_obs - noise. 
- - How to avoid noise absorbing everything : add a regulariser 
- - How to avoid the dynamics becoming an arbitrary smooth field? Impose dynamics-consistency coupling : the denoised states at consecutive time-steps must map to one another under a shared MLP operator - i.e. forward and backward
- - How does this work under the cross-validated train-test block training? We want a single MLP? -> One contiguous latent noise_full is kept in the optimiser group over all train columns. During gradient descent, we only pull the corresponding columns to compute the loss. The noise tensor is then regularised once. 
- - This means noise is not available to the test data. In future iterations, we can consider comparing the estimated noise tensor against the observed variability in test data. Or more concretely, given that we are currently working with synthetic data, we can evaluate how good the noise tensor is.
