Yesterday we set up a simple, synthetic autoregressive model discovery task - synthetic_data_v2.

But there are a few fundamental architectural features of EDGAR that feels unnatural for discovering autoregressive models. 

1. We give EDGAR some hard-coded number of points from the past (20 in the case of synthetic_data_v2). But there is no way 
for EDGAR to drill into these twenty points and find a pattern within these 20 points before making a new suggestion. 
2. EDGAR doesn't have access to what the distribution of the parameters look like. So it's hard for it 
to figure out which of the parameters are valueable and which are not adding much. For example, it 
proposed a Taylor expansion version of cos(x), but it doesn't think to reduce the number of parameters by
recosgnising this identity. 

More concretely, we want think about 
- How can we have a workflow where EDGAR is able to inspect these windows of timelines before making a suggestion? Or do we think
the current workflow is fine? After all, EDGAR gets an image diagnostic for what the time series looks like, so it should be able
to learn from the time series. The main hangup stems from the difference between our current process and the way a deep-learning model
learns an autoregressive model. Given that we don't want to build a neural network but instead produce a more interpretable model, 
it's unclear what the right step forward is. 

## After conversation with Fable 
"This isn't how deep learning models learn autoregressive models" - is a red herring. "Drilling into the window" is a fitting job
which is already done properly by gradient descent. But then, this assumes that the loss differences between structures are large enough
to survive fitting noise, which may not hold in autorgressive models. 
A better question to ask it, does the mutation operator receive enough evidence to make informed rather than blind proposals? 

Two ways in which the current input to the mutation operator is limiting 
1. The LLM never sees the fitted parameter values. Having access to this will expose dead parameters 
2. The feedback has no lag-resolution. There is no way to figure out which of the 20 lags matter. 

Fable's suggestions and my comments 
- a. Put parent parameter summaries in the prompt : parameter key, median +- IQR/std 
- b. Add lag diagnostics to the feedback : either numeric (e.g. R2 of residual regressed on each of the 20 lags) or visual (replace/augment) the right panel with residual-vs-x(t-k) for a few k. 
- c. Only if a & b are insufficient, add an agentic route - tool-use/REPL or a fixed per-generation data analyst. b is already a lightweight version of this to some extent. 

Q: "Is there some quantitative way of getting an intuition for differences in losses between model structure and parameters? Your claim " argument 2 assumes loss differences between structures are large enough to survive fitting noise, which for nearby AR orders may not hold" is interesting, and I wonder if there is a generalisable way to figure out which of the two possible regimes a dataset lives in. Perhaps this is impossible to answer."
The measured loss of a fitted structure S splits into four parts:

L(S) = σ²_noise  +  B(S)  +  E(S)  +  penalty(S)
       noise floor  structural   fitting     1e-5 · n_params
       (irreducible) bias        excess

- σ²_noise — the floor no model beats. Known here: process_noise = 0.005 ⇒ one-step MSE floor = 2.5×10⁻⁵.
- B(S) — approximation error of the best possible parameters for that structure. This is what selection is supposed to rank.
- E(S) — how far the param_estimator + Adam actually landed from those best parameters. This varies between re-derivations of the same structure and is pure noise from selection's point of view.
- Plus eval-sampling noise: the measured loss is a mean over 16 discover cells × 160 predicted points, so it fluctuates with which cells you evaluate on.

Selection can distinguish S₁ from S₂ iff ΔB + Δpenalty ≫ (fitting-excess spread + eval-sampling SE). That ratio is the "selection SNR," and every term in it is measurable:

Four measurable quantities

1. Eval-sampling noise — paired, from data you already store. sample_losses (per-cell, no penalty) is saved on every program, and competing programs are evaluated on the same 16 cells. So the right statistic is the paired comparison (this is Vuong's test for non-nested models): for programs A and B, compute per-cell differences dᵢ = ℓᵢ(A) − ℓᵢ(B), then t = mean(d)/(std(d)/√16). Pairing cancels per-cell heterogeneity (each cell has its own A, p, q, so marginal losses vary wildly, but the difference doesn't). |t| ≫ 2 ⇒ structural regime; |t| ≲ 2 ⇒ selection is coin-flipping between these two. Computable post hoc from population.jsonl for any pair of adjacent-ranked programs in any existing run.

2. Discover↔validate rank agreement — zero extra computation. Both splits' losses are stored per program on disjoint cell sets. Spearman correlation of discover vs validate ranks among the top-k programs is a direct empirical readout of whether loss differences at the top of the population generalize or are sampling noise. High correlation ⇒ tournament is meaningful; near zero ⇒ drift regime.

3. Fitting-excess spread — one small experiment. Refit a fixed structure R times with jittered initial guesses (the pipeline is deterministic given the init, so jitter is how you probe it) and take the std of final losses. This σ_refit is the reproducibility floor of the tournament: any ΔB or Δpenalty below it is invisible to selection no matter how much eval data you have.

4. A priori gap estimates — the "oracle" for ΔB without fitting both. For linear lag structure this is classical: the PACF at lag k estimates the fractional loss reduction of AR(k−1)→AR(k), so φ²ₖₖ × residual variance ≈ the gap. Generalized: regress the current best model's residual on a candidate feature (a lag, a nonlinear transform); R² × residual variance = the loss headroom that feature offers. And a nonparametric one-step predictor (k-NN on the delay embedding) estimates the total headroom: current best loss − floor = how much structural bias remains to be found at all. If that headroom is smaller than the noise from (1)–(3), no feedback-channel improvement helps — you need more data or better fitting, full stop.

The concrete case that motivated this

For Taylor-vs-cos, ΔB is near zero by construction (they make almost the same predictions), so the only signal selection has is Δpenalty ≈ 3–4×10⁻⁵ (three-ish extra params × 1e-5). Note that's the same order as the entire noise floor. Whether simplification pressure can act reduces to a single measurable question: is σ_refit < ~3×10⁻⁵? If gradient descent lands within ~1e-5 of the same loss every time, the penalty deterministically decides the tournament and the current architecture will eventually collapse the Taylor form. If refits scatter by 1e-4, the penalty is sub-threshold and no amount of prompting fixes it — you'd have to either raise the penalty or give the LLM the fitted-parameter view so the collapse happens at proposal time instead of at selection time. That's a crisp adjudication of yesterday's concern #2.

On "is it impossible in general?"

The truly unknowable part is ΔB for a structure nobody has fit yet — no free lunch there. But the regime question doesn't need that. It needs the noise scale of your tournament (items 1–3, all measurable) compared against the gap scale you care about (penalty increments, PACF-estimated lag gaps, headroom to the floor — item 4). That comparison is answerable per dataset, cheaply, and mostly from artifacts EDGAR already writes.
