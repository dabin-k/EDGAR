Set up a synthetic project called "synthetic_composite_system", which defines a new class of problems.

Suppose you have an observable y is described by = f(g_1(x_1), g_2(x_2), ..., g_N(x_N)).
We assume that g_i(x_i) individually describes a sub-component of the system well and that 
EDGAR's job is purely to identify f that composes these sub-component systems together. 

We start with the simplest case where each model is separable - i.e. each g_i depends only on its own input x_i and its own parameters.
- In this case, the example is very similar to what EDGAR does already. The only difference is that the discovered model needs to be able to 
call the sub-component function. 
- We assume that all sub-components are differentiable (i.e. we can fit the parameters using gradient descent). But we don't assume that the final model f is necessarily differentiable.
- We want to inhibit the LLM from cheating by changing the subunit. Therefore, the sub-component function should be callable but not modifiable. Let's specify the sub-component functions in apply_model_fn. 

## Example model: Plant growth rate 

```python
import numpy as np

def g_light(L, K_L=200.0):
    return L / (K_L + L)

def g_nitrogen(N, K_N=2.0):
    return N / (K_N + N)

# True model: 
def growth(L, N, mu_max=1.5):
    return mu_max * np.minimum(g_light(L), g_nitrogen(N))
```

1. What is a sample? 
- Each plant is a sample. For each sample, we have a sequence of length T, which describes the rate of growth at each time point. Notice, this is a simple model, and we don't need any memory - the instantaneous recording of L and N are sufficient to determine the growth rate of each plant at T 
2. What is a trial 
- Each trial is a time point T. The data will therefore be an n_plants x T matrix containing the growth rate - i.e. we assume that the growth rate was measured at the same time interval for each plant.
3. What's in the data? 
Data contains:
- Observed growth_rate : matrix with shape n_plants x T 
- Observed nitrogen : matrix with shape n_plants x T
- Observed light : matrix with shape n_plants x T
4. What are the parameters? 
- There are two types of parameters, but note that all parameters are sample specific. 
 - component-level parameter : e.g. K_L and K_N (e.g. dependent on how sensitive each plant is to each variable)
 - model-level parameter : e.g. mu_max 
- Let's start by just running gradient descent on everything all at once. But we may have to separate this into sub-processes - e.g. first run n_steps to optimise the sub-component-level parameters and then n_steps to optimise the model-level parameters, and then iterate. 


## How this will actually look in model_fn and apply_model 

```python
def model(data, params, components):
    ''' 
    Args 
        data (dict): single plant, data["L"] and data["N"] shape (T,)
        params (dict): scalar per-plant parameters
        components (dict): fixed sub-components, e.g. components["g_light"](L, K_L)
    Returns
        growth rate, shape (T,)
    '''
    L = data["L"]
    N = data["N"]
    
    K_L = params["K_L"]
    K_N = params["K_N"]
    mu_max = params["mu_max"]

    g_light = components["g_light"]
    g_nitrogen = components["g_nitrogen"]

    return mu_max * jnp.minimum(g_light(L, K_L), g_nitrogen(N, K_N))


def apply_model(model_fn, data, params):
    ''' 
    Args 
        model_fn: per-plant model, model_fn(data, params, components)
        data (dict): contains 
            data["growth_rate"] shape (n_samples, T)
            data["L"] shape (n_samples, T)
            data["N"] shape (n_samples, T)
        params (dict): leaves have a leading sample axis
    '''
    components = {"g_light": g_light, "g_nitrogen": g_nitrogen}

    return jax.vmap(lambda d, p: model_fn(d, p, components))(data, params)
```

Notes 
- Models can't see g_light / g_nitrogen otherwise: generated code is exec'd in an isolated namespace, so `apply_model` passes them in via `components`. 
- g_light and g_nitrogen are `SubComponent` dataclasses (data_loader/sub_components.py) holding `fn`, `latex` and `n_params`; they're callable, so `components["g_light"](L, K_L)` works directly. 
- `ground_truth_model` in load_data.py is the reference implementation of this signature. 
- `parameter_estimator(data)` is unchanged: EDGAR doesn't pass `components` to it, so seed estimators inline the saturation formulas. Could add an optional `apply_param_est` hook (like `apply_model`) later if needed.
